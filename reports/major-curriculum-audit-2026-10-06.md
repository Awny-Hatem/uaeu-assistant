## Scope and honesty boundary

The public demo at `https://uaeu-assistant.vercel.app` was tested before changes; its `/api/health` revision was `ac5767396beca6de8a584bac1a0dd8e8d08b5734` and content fingerprint was `ad61f1c419e35210499f51108cc152296f2c870848c1f5ea0d4df3d5c07d3a15`. The local checkout already had uncommitted knowledge files and therefore was not identical to that deployment. The new data and code were retested through the *local actual chat route*, not deployed. There has been no deployment, so this report does not claim the public chatbot is fixed. The local content fingerprint after the additions was `69f7ffd1626c73e858dd8b8c74459ac529dc0d6eb703e199561455deb8536316`.

“Passed after” below means the local actual route returned HTTP 200, the correct source-specific fact, a UAEU citation, and a `knowledge:` evidence ID naming a new file. Nineteen cases also passed an ablation in which all newly marked curriculum documents were removed from the retrieval input: no extractive answer was available. This establishes that the new RAG records, rather than an existing FAQ or model pretraining, supplied these answers. It does not certify students' personal degree audits or registration eligibility.

## Complete answer-source architecture

1. `app/api/chat/route.ts` handles context, urgent/safety and privacy boundaries, FAQ matches, semantic selection, service guides, retrieval, grounded generation, and citations. `lib/query-understanding.ts` identifies subjects, courses, cohorts and requested facts.
2. `data/verified-answers/*.json` supplies canonical bilingual answers. `lib/faq.ts` can match these directly; `lib/semantic-routing.ts` asks the configured OpenAI/Gemini provider to select IDs from a closed approved catalog and then selects relevant full approved bodies. This was often the *wrong* source for the tested degree questions (e.g., semester load for total degree credits).
3. `data/knowledge/*.md` supplies approved official-source excerpts. `lib/knowledge-files.ts` loads only approved, recent, official-UAEU documents and supports lexical retrieval. The new `lib/curriculum-retrieval.ts` selects a matching section from explicitly marked `curriculum: true` records for certain English program/course questions, before unrelated canonical answers can preempt it. Its answer is extractive: published section text plus that record's UAEU citation, not an unsourced model generation.
4. Optional `data/embeddings.json` is built by `scripts/ingest.ts`, read by `lib/vector-rag.ts`, and used only with `GEMINI_EMBEDDING_SEARCH=enabled`, a Gemini key and a matching corpus fingerprint. Both tested environments reported zero active vector chunks; the local active embedding path was disabled. No reindex is required for the active lexical/extractive path; newly approved Markdown is read on request.
5. `data/service-guides/*.json` is matched by `lib/service-guides.ts` for guided procedures. `data/communications.json` supplies related links, not course facts. `lib/ai-provider.ts` calls OpenAI Responses or Gemini for selection/generation; it does not search UAEU's website or contact a UAEU student-record API during an answer. `lib/source-evidence.ts` and `lib/claim-verifier.ts` check generated claims and source IDs.
6. SQLite `data/chatbot.db` via `lib/db.ts` stores prototype users, sessions, messages and analytics, not curriculum facts. No external curriculum database, live course schedule, SIS, portal access or enrollment check exists in this repository.

## Remaining gaps and uncertainties

- The deployed demo is still on its old build and knowledge fingerprint. Publish a fresh Git build, then compare its `/api/health` revision/content fingerprint and rerun the 19 factual tests against the deployed route before claiming a production improvement.
- The configured live selector was intermittently unavailable during local testing (HTTP 503). This is an availability issue, not proof that six previously covered facts became incorrect, but those six need a successful live after-retest.
- Official IT sources conflict: the current catalog says **120** total credits, while the Fall 2025–26 model plan PDF says **130**. The chatbot now exposes the difference instead of silently merging them; a student's assigned degree audit/advisor must determine applicability.
- Mechanical Engineering Fall 2025–26 and 2026–27 model first semesters use different calculus codes (MATH105 vs MATH130). The generic answer selects the newest Fall-entry model and labels it; Spring-entry students and other cohorts need their own plan.
- The Mechanical Engineering 2026–27 model PDF also places MECH384 in its sequence, while the current program requirements page's 68-credit required-course list does not enumerate it. The generic required-course answer is explicitly the program-page list, not a resolution of that cohort discrepancy.
- The CS Fall 2025 PDF prints `CSEB119 (Co)` by CSBP121, apparently inconsistent with the course code. The record preserves this uncertainty and does not invent the corrected rule.
- Extractive curriculum answers are currently English-only. Arabic requests continue through the existing canonical/grounded path and were not claimed fixed here.
- No personal degree-audit, completed-course, live offering or enrollment API is connected. The bot can explain published prerequisites and model sequence, not certify that a particular student may register or has graduated.
